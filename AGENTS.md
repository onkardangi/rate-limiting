# AI-Assisted Development Guidelines

This repository is a learning project. The goal is not merely to reach the final architecture; the evolution of the architecture is itself part of the product.

## Rules

1. Do not implement future phases unless explicitly requested.
2. Prefer the simplest design that satisfies the current requirements.
3. Do not introduce infrastructure before a demonstrated requirement exists.
4. Do not prematurely optimize.
5. Do not create abstractions for hypothetical future requirements.
6. Every major architectural change should correspond to a problem we have identified.
7. Preserve existing behavior unless the current task explicitly changes it.
8. Add tests for new behavior.
9. Keep classes focused and naming explicit.
10. Prefer readable code over clever code.
11. Before introducing a dependency, explain what current problem requires it.
12. Before making a significant architectural change, identify the limitation in the existing design that motivates it.
13. Do not automatically implement suggestions listed under "future work."
14. Treat documentation of architectural reasoning as part of the project.
